## 五、核心问题分析

### 5.1 为什么 pred_actual_ratio 只有 0.73 而非 0.95？

经过深入分析，当前模型的系统性低估（bias -26.77%）是**模型本身的结构性问题**，不是代码 bug：

1. **P0/P1 修正仅生成文件但未替换预测列**
   - `apply_p0_p1_fix_v2.py` 计算了 P0 修正后的 `power_pred_p0` 列，但最终只将原始 `power_pred`（未修正值）保存到输出
   - 实际测试：`v159_fix` 和 `fixed_full` 的 `power_pred` 值完全相同，说明没有任何修正被应用

2. **Guard 选择了 V0（原始预测）**
   - V0 和 V1（假设应用了 P0/P1）在 valid 集（7-8 月）上的 guard score 表现决定了最终选择
   - 当前只有 V0 和 V1 可用，V1DD/V3 不存在
   - Guard 机制基于 valid 集优化，但 valid 集（夏末）和 test 集（秋冬-早春）的辐照和发电特征差异较大，导致基于 valid 集的 guard 选择可能不适合 test 集

3. **根本矛盾**
   - 修复文档期望达到 `ratio ≈ 0.9488`，但当前模型的 V0 预测只有 `ratio ≈ 0.7323`
   - 两者差距约 22 个百分点，远超 P0/P1 修正的改善能力
   - 即使正确应用 P0/P1 修正，根据脚本内嵌的测试输出，P0 修正仅将 bias 从 -27% 改善到约 -15%（城市聚合级），距离 -5% 仍有较大差距

### 5.2 评估口径差异

当前评估使用严格口径（排除 BAD 站点、功率 > 0），与修复文档中的周二口径一致。不同的口径会产生截然不同的 ratio：
