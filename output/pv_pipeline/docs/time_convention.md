## 1. 概述

本文档记录项目中各数据源的时间约定、对齐方式和处理逻辑。

### 1.1 涉及的时间数据

| 数据源 | 时间粒度 | 时区 | 说明 |
|--------|----------|------|------|
| 功率数据 | 逐小时 | 北京时间 (CST, UTC+8) | 整点瞬时值 |
| ERA5 气象 | 逐小时 | UTC | 需要 +8h 转换 |
| TCC 云量 | 逐小时 | UTC | 需要 +8h 转换 |
| STRD 辐射 | 逐小时 | UTC | 需要 +8h 转换 |
| g_blend | 逐小时 | 北京时间 | 融合后的辐照度预测 |

### 1.2 时间对齐问题

时间对齐问题可能导致：
- 辐照度峰值与功率峰值存在 1 小时偏移
- 6点、19点边界时段误差偏高
- 快速云移场景预测不准

## 2. 当前时间处理逻辑

### 2.1 原始数据时间戳含义

```python
# 功率数据: 北京时间整点值
# 例: 2025-07-01 12:00:00 表示 12:00 时刻的功率

# ERA5/ TCC/ STRD: UTC 时间
# 例: 2025-07-01 04:00:00 UTC = 2025-07-01 12:00:00 CST
```

### 2.2 数据处理流程

```
原始 ERA5 (UTC)  →  +8小时  →  项目内部时间 (CST)
原始功率 (CST)   →  直接使用  →  项目内部时间 (CST)
```

### 2.3 g_blend 时间对齐

`g_blend_pred` 是辐照度融合预测，当前假设：
- g_blend 峰值时间与功率峰值时间对齐
- 如有偏移，需要在 `check_gblend_time_alignment.py` 中诊断

## 3. 峰值偏移诊断结果

### 3.1 诊断方法

通过互相关分析，计算 g_blend 与功率在不同滞后（lag）下的相关性：

```python
lag_range = [-2, -1, 0, +1, +2]  # 小时
corr = correlate(power, g_blend.shift(lag))
best_lag = argmax(corr)
```

### 3.2 诊断结论

根据 `time_alignment_diagnosis.csv` 分析：
- 大多数站点在 lag=0 时相关性最高
- 部分站点在 lag=-1 或 lag=+1 时更优
- 整体偏移在 ±1 小时内，属于可接受范围

### 3.3 固定 Pipeline 采用的对齐方式

```python
# 当前版本: 不做额外时间偏移
g_blend_aligned = g_blend

# 如需调整，可使用:
# g_blend_aligned = g_blend.shift(best_lag)
```

## 4. 6点和19点误差偏高的原因

### 4.1 物理原因

1. **功率分母小**
   - 早晚功率接近 0，MAPE 天然偏高
   - 即使 1 MW 误差，在 5 MW 功率时也是 20%

2. **太阳高度角低**
   - 低入射角放大组件朝向、倾角差异
   - 阴影、遮挡影响更显著

3. **辐照度响应滞后**
   - 辐照度变化到功率响应存在时滞
   - 早晨启动、傍晚衰减时段尤为明显

4. **数据噪声**
   - 小功率时段并网数据噪声比例高
   - 弃光、限电等操作影响

### 4.2 为什么需要单独评估

- 6点和19点是光伏"日出/日落"关键时段
- 这些时段的预测准确性影响：
  - 日负荷曲线早高峰/晚高峰预测
  - 调度计划制定
  - 储能充放电策略

## 5. 修复措施

### 5.1 Dawn/Dusk Floor 修正

```python
# 边界时段应用 floor 修正
DAWN_DUSK_HOURS = [6, 7, 17, 18, 19]

floor_factor = quantile(power_mw / max(p_base, eps), 0.20)
floor_factor = clip(floor_factor, 0.05, 0.80)

power_pred_fixed = max(power_pred, p_base * floor_factor)
```

### 5.2 策略选择

| 时段 | 推荐策略 | 说明 |
|------|----------|------|
| 6-7时 | baseline | 使用基础模型预测 |
| 8-10时 | baseline | 正常辐照度模型 |
| 11-16时 | floor_base_1.0 | 添加 p_base 下限 |
| 17-18时 | floor_base_0.8 或 blend_70 | 傍晚衰减修正 |
| 19时 | floor_base_1.0 | 日落边界 |

## 6. 建议与后续优化

### 6.1 短期优化

1. **引入更精细的时间对齐**
   - 按站点单独计算最佳 lag
   - 在训练阶段引入时滞特征

2. **增强早晚辐照度模型**
   - 引入太阳高度角特征
   - 加入日落前后的专用特征

3. **使用 WAPE 替代 MAPE**
   - 低功率时段 MAPE 不稳定
   - WAPE 更适合评估总量误差

### 6.2 中长期优化

1. **引入辐照度到功率的物理模型**
   - 使用 pvlib 计算 POA 辐照度
   - 考虑温度、倾角、方位角影响

2. **增加云图预测**
   - 引入卫星云图数据
   - 改善快速云移场景预测

3. **引入 Kriging 插值**
   - 考虑空间相关性
   - 改善沿海/内陆差异
