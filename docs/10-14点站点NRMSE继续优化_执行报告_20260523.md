### 修改 1：`select_final_prediction_by_guard.py` — `compute_hour_metrics` 增加 `site_nrmse_mean_pct`

**位置**：`scripts/select_final_prediction_by_guard.py` 第 179-191 行

**内容**：在 `compute_hour_metrics()` 的返回字典中新增站点平均 NRMSE 计算逻辑：

```python
# site-level NRMSE: per-site RMSE / mean(capacity), then average across sites
site_nrmse_vals = []
for _, sg in sub_df.groupby("site_id"):
    yt_s = pd.to_numeric(sg["power_mw"], errors="coerce").to_numpy(dtype=float)
    yp_s = pd.to_numeric(sg[pred_col], errors="coerce").to_numpy(dtype=float)
    cap_s = pd.to_numeric(sg["capacity_mw"], errors="coerce").to_numpy(dtype=float)
    m_s = np.isfinite(yt_s) & np.isfinite(yp_s) & np.isfinite(cap_s) & (cap_s > 0)
    if not m_s.any():
        continue
    rmse_s = float(np.sqrt(np.mean((yt_s[m_s] - yp_s[m_s]) ** 2)))
    cap_mean_s = float(np.nanmean(cap_s[m_s]))
    if cap_mean_s > 0:
        site_nrmse_vals.append(rmse_s / cap_mean_s * 100.0)

return {
    ...
    "site_nrmse_mean_pct": float(np.nanmean(site_nrmse_vals)) if site_nrmse_vals else np.nan,
    ...
}
```

### 修改 3：新建 `scripts/apply_midday_residual_specialist.py`

**文件路径**：`scripts/apply_midday_residual_specialist.py`（新建）

**核心逻辑**：

1. **输入**：读取 `distributed_predictions_midday_site_calibrated_full.pkl`（若不存在则用 `fixed_full`）
2. **train 集**：学习 `residual_norm = (power_mw - power_pred) / capacity_mw` 的分层中位数
   - 层级：`site_id × hour × month` → `site_id × hour` → `hour × capacity_bucket` → `hour`
   - 样本不足时自动向高层回退
   - 自动 shrinkage：`shrink = n_eff / (n_eff + 80.0)`
3. **valid 集**：网格搜索最优 `lambda ∈ {0.25, 0.40, 0.55, 0.70, 0.85, 1.00}` 和 `clip_norm ∈ {0.04, 0.06, 0.08, 0.10, 0.12}`
   - 目标函数：`valid 5 小时平均站点 NRMSE` 最低
4. **应用**：仅对 10-14 小时做修正：`adjusted = pred + lambda × residual_norm × capacity`

## 五、结论与后续建议

### 本轮结论

1. **选择器指标修正有效**：`site_nrmse_mean_pct` 进入选择器后，10-14 小时的版本选择更加贴合站点级误差目标，最终 5/5 小时全部改善，平均下降 1.66pp（10.31%）。
2. **残差专家候选暂未生效**：`MiddayResidualSpecialist` 在 valid 上反而轻微恶化，被 guard 正确拒绝。这并不意味着残差方法无效——可能原因包括：
   - 乘法校准后残差分布已接近对称，加性修正增益有限
   - `lambda=0.25` 说明最优策略接近不做修正（数据不支持残差修正方向）
   - train/valid/test 分布差异导致 valid 最优参数在 test 上无正向效果

### 后续排查方向（按方案第 10 节）

1. **检查残差方向**：查看 `metrics/midday_residual_specialist_params.csv`，确认 `residual_norm_median` 方向是否与预期一致
2. **若 valid 改善但 test 不改善**：增大 shrinkage 强度（将 `n_eff + 80` 改为 `n_eff + 160`）
3. **若城市级误差略高**：可将 `city_rel_err` 上限从 8.0 放宽到 10.0，让站点 NRMSE 优先
4. **检查高误差站点集中度**：若最差 NRMSE 集中在 2-5 个站点，下一步应针对这些站点做单独参数，而不是继续全局调参
