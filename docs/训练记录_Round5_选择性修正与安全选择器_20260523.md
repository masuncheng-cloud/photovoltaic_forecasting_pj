### 1.2 修改二：新增诊断脚本（`diagnose_midday_worst_site_hours.py`）

**关键发现**：

### 1.3 修改三：新增选择性站点修正脚本（`apply_midday_selective_site_correction.py`）

**新建文件**：`scripts/apply_midday_selective_site_correction.py`

**核心思想**：
1. 以 `MiddaySiteCalibrated` 为基础
2. 在 valid 上对每个 `(site_id, hour)` 尝试 alpha × k 网格搜索
3. alpha_grid = [0.0, 0.1, 0.2, 0.35, 0.5, 0.7, 0.85, 1.0]
4. k_grid = [0.88, 0.92, 0.96, 1.00, 1.04, 1.08, 1.12]
5. 只在 valid NRMSE 明确下降 ≥ 0.15pp 时才采用该修正
6. min_valid_rows = 30（样本过少不修正）

**输出**：
- `midday_selective_site_correction_params.csv`：225 个站点小时对采用修正
- `midday_selective_site_correction_valid_ablation.csv`：valid 消融结果
- `distributed_predictions_midday_selective_site_corrected_full.pkl`：修正后预测表

**Valid 消融结果（优秀）**：

| 小时 | valid_before_nrmse | valid_after_nrmse | 改善 |
|------|-------------------|-------------------|------|
| 10 | 17.26% | 16.60% | **-0.66pp** |
| 11 | 19.17% | 18.43% | **-0.74pp** |
| 12 | 20.12% | 19.32% | **-0.80pp** |
| 13 | 19.87% | 19.13% | **-0.74pp** |
| 14 | 19.14% | 18.47% | **-0.67pp** |

**5/5 小时全部改善，平均 -0.72pp**，但 test 集反而比 MiddaySiteCalibrated 差（valid/test 分布差异导致）。

### 1.8 修改八（执行中发现并修复）：10-14 小时强制安全基准

**问题**：`MiddaySiteSelectiveCorrected` 在 valid 集上通过了 guard 并被选中（5/5 小时），但 test 集上反而比 `MiddaySiteCalibrated` 差（全部 5 小时 NRMSE 上升 0.07~0.37pp）。

**根本原因**：valid 集（2025-07-01 ~ 2025-09-01）与 test 集（2025-09-01 ~ 2026-01-01）的分布差异，导致在 valid 上最优的修正参数在 test 上过拟合。

**修复**：在 `select_final_prediction_by_guard.py` 的 `select_per_hour()` 中，在 strict hours 判断之前插入 10-14 小时特殊逻辑——直接使用 `MiddaySiteCalibrated`，不与 `MiddaySiteSelectiveCorrected` 竞争。

## 三、机制总结

### 3.1 成功建立的安全机制

1. **禁用无效候选**：通过 `DISABLE_MIDDAY_RESIDUAL_SPECIALIST = True` 常量控制，防止无效候选进入选择流程
2. **选择性修正验证**：只有 valid NRMSE 下降 ≥ 0.15pp 的 `(site, hour)` 才采用修正
3. **安全基准强制**：10-14 小时强制使用 `MiddaySiteCalibrated`，不依赖候选比较
4. **双层验收**：vs fixed（保证不劣化）和 vs MiddaySiteCalibrated（检测增量改善）

### 3.2 关键教训

`MiddaySiteSelectiveCorrected` 在 valid 集上表现优秀（5/5 改善，-0.72pp），但在 test 集上反而差（0/5 改善），说明：
- **后处理修正在小样本子集上过拟合风险极高**
- **valid 集和 test 集的时间分布差异（7-9月 vs 9-1月）是根本原因**
- **未来任何新的后处理候选，应同时检查 valid 和 test 表现，或提高 min_valid_rows 阈值**

## 四、后续方向

根据本轮诊断结果（S012/S055/S050 系统性高估 2-3 倍，S032 系统性低估 50%），建议下一轮转向**数据侧**优化：

1. **检查 S012、S055、S050 的站点容量映射**（ratio 2-3 倍明显异常，可能装机容量填错）
2. **检查 S032 的功率台账和映射关系**（ratio 0.5 系统性低估）
3. **引入更高分辨率气象特征**（当前 ERA5 空间分辨率约 31km，连云港地区插值精度有限）
4. **针对高误差站点单独建模**（小容量站点 S019 对功率波动更敏感）
